A. FREEBUFF TOTAL SPENDABLE BALANCE BADGE
======================================================================

USER-OBSERVED REFERENCE

Freebuff's own UI shows one compact Freebucks badge representing the amount
currently spendable.

Observed example:

    daily remaining: 10 FB
    wallet:          15 FB
    total spendable: 25 FB

FastPrompter already displays:

    daily FB: 10/105 FB
    Wallet: 15 FB

but does not display the corresponding compact total "25" badge in the
Freebuff account header.

IMPLEMENTATION TRUTH

The provider already exposes:

    snapshot.provider_metadata["wallet_balance"]
    snapshot.provider_metadata["wallet_monthly_bonus"]
    snapshot.provider_metadata["total_balance"]

The Freebuff provider currently populates:

    "total_balance": fb.get("balance")

The HTTP parser documents the vendor semantics:

    balance = daily.remaining + wallet.balance

Therefore DO NOT invent a second quota model and DO NOT treat the wallet as
another percentage window.

DESIRED UI

In the AI Usage Limits hover card, render a small Freebuff-style amount badge
on the Freebuff account header row.

Conceptually:

    Freebuff (starter)   [25]

The badge should visually read as an amount/currency pill, not as another
percentage gauge.

It should be compact enough not to disturb the existing hover-card geometry.

The detailed rows remain unchanged:

    daily FB: 10/105 FB — resets ...
    Wallet: 15 FB · never expires ...

The badge is the aggregate quick-glance value.
The detailed rows explain where that value comes from.

SOURCE OF TRUTH

Primary:

    provider_metadata["total_balance"]

Fallback is allowed only when total_balance is absent AND both component values
are trustworthy:

    available daily remaining amount + wallet balance

Do not calculate a fake total from percentages.

Do not display a guessed badge when provider state is unavailable/error/auth
required.

For stale snapshots, preserve the existing stale semantics and make the badge
visually consistent with stale account presentation rather than presenting it
as fresh truth.

FORMAT

Whole numbers:

    25

Non-whole values:

    use the project's compact numeric formatting;
    do not emit distracting long floating-point tails.

Zero:

    displaying 0 is valid when the provider explicitly proves total_balance=0.

Do not hide a proven zero merely because it is falsey.

LIKELY FILES

    src/fastprompter/ui/limit_gauges.py
    src/fastprompter/core/usage_limits/providers/freebuff.py
    src/fastprompter/core/usage_limits/providers/_freebuff_http.py
    tests/test_usage_limits_freebuff.py
    tests/test_usage_limits_tooltip_compact.py
    tests/test_limit_hover_card.py

Avoid provider changes unless necessary; the required metadata already exists.

ACCEPTANCE

Given:

    daily remaining = 10
    wallet = 15
    total_balance = 25

hover header visibly contains:

    25

while detail still contains both:

    10/105 FB
    Wallet: 15 FB

Given:

    daily remaining = 0
    wallet = 15
    total_balance = 15

badge:

    15

Given explicit:

    total_balance = 0

badge:

    0

Given unavailable/auth-failed state with no trustworthy total:

    no fabricated numeric badge.

No additional network request may be introduced merely to render the badge.

B. CRASH — TRASH VISION TOGGLE CALLS REMOVED METHOD
======================================================================

USER-OBSERVED EXCEPTION

    FastPrompter Error:

    Traceback (most recent call last):
      File "...src\\fastprompter\\main.py", line 13383,
        in toggle_trash_vision
        self.refresh_categories()
    AttributeError:
        'FastPrompter' object has no attribute 'refresh_categories'

ROOT CAUSE

Current source contains:

    def toggle_trash_vision(self, checked):
        ...
        self.refresh_categories()

but FastPrompter no longer defines:

    refresh_categories()

The modern category UI paths are:

    build_categories()
    rebuild_cat_combo(keep=...)

This is a stale call left behind by the category rebuild/refactor.

DO NOT solve this by reintroducing a compatibility method named
refresh_categories() unless repository archaeology proves that such an API is
still intentionally required by multiple callers.

There is currently no legitimate reason to resurrect dead API surface for one
stale caller.

CORRECT BEHAVIOR

Toggling "Show Trash" must:

    update trash_vision persisted state;
    create the Trash category backing state when needed;
    add/remove Trash from cats_order according to existing semantics;
    rebuild the visible category UI through the CURRENT canonical path;
    preserve current project identity when possible;
    respect hidden_categories;
    keep category number buttons synchronized;
    never raise;
    mark the profile dirty exactly as required.

Preferred reconciliation:

    capture current category identity;
    mutate Trash visibility/order;
    call the current identity-preserving category rebuild path.

Investigate whether:

    rebuild_cat_combo(keep=current_category)

is the correct canonical route.

Do NOT blindly replace the call with build_categories() if that needlessly
resets the active project to row 0.

Remember:

    build_categories()

currently resets the combo to index 0.

That may be correct for profile boot / full restore, but is undesirable for a
simple settings toggle unless explicitly intended.

REGRESSION TESTS

Add focused tests proving:

1. Toggle Trash OFF from a normal project:
       no exception;
       current project remains selected;
       Trash disappears from visible navigation as intended.

2. Toggle Trash ON from a normal project:
       no exception;
       current project remains selected;
       Trash becomes reachable according to Trash visibility policy.

3. Toggle while current project ordering contains hidden projects:
       no hidden project accidentally reappears;
       combo identity and cats_order do not become row-index confused.

4. Toggle while Trash state already exists:
       no duplicate "Trash" entry in cats_order.

5. Repeated ON/OFF/ON:
       idempotent;
       no duplicate widgets;
       no duplicate combo rows;
       no stale number-tab buttons.

6. Profile save/reload:
       persisted trash_vision state produces the same visible result.

Also grep the full repository for:

    refresh_categories

After the repair there must be no executable stale caller unless a remaining
definition/call is independently valid.

======================================================================

    Ночь

    Emoji Day State

    Show an emoji (...) instead of the time-of-day word

    self.data.get("date_emoji", "False")

while main.py profile widget resync currently registers:

    ("cb_date_emoji", "date_emoji", "True")

These defaults must not disagree.

Investigate the canonical DEFAULT_PROFILE value and make every path derive from
that single truth.

Do not merely change the screenshot-visible checkbox.

Required invariant:

    persisted date_emoji
    == settings checkbox state
    == profile-switch checkbox state
    == topbar rendering decision

When:

    date_daypart = True
    date_emoji = True

When:

    date_daypart = True
    date_emoji = False

When:

    date_daypart = False

neither textual daypart nor daypart emoji is rendered.

Toggling the checkbox must update the topbar immediately without restart.

Profile switching must not manufacture a different value from an inconsistent
fallback default.

Add regression coverage for:

    False -> True live toggle
    True -> False live toggle
    profile A True / profile B False
    missing legacy key migration/default behavior
    Russian UI with emoji enabled
    no dependency on opening Settings before correct rendering
