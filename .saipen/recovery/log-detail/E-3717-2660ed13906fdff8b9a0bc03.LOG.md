- 01.10.26 01:11 [E-3717] [parent: E-3716] [T-1362] [agent: buffy] [op: checkpoint-63a243d9dd744dccb1d4383490c4aad4] DEC: DEC: the receipt binding conflates two different questions. The HEAD equality asks 'was this recorded against this exact commit', which is provenance; the source_tree_fingerprint asks 'is the verified code byte-identical', which is the actual evidence claim. Because freshness._is_saipen_path excludes .saipen/ from git-delta-v1, a protocol-only commit changes HEAD while leaving the fingerprint untouched, so the provenance half rejects evidence that the evidence half still fully vouches for. That is what makes fresh-clone conformance an unsatisfiable fixed point: committing a receipt advances HEAD and invalidates that receipt. Chosen remedy (conventional default): make the HEAD half ancestor-tolerant and keep the fingerprint half strict. Accept receipt.source_head == live HEAD, or receipt.source_head is an ancestor of live HEAD (git merge-base --is-ancestor), and still require exact source_tree_fingerprint equality. Rationale: the fingerprint is the load-bearing check and it stays byte-exact, so no stale-code evidence can be admitted; only provenance loosens, and only along the project's own first-parent history, so a receipt from a divergent branch or an unrelated clone is still rejected. This also removes the post-ship replay treadmill: a receipt now survives a protocol-only commit instead of being invalidated by it.
