Every verb on the instance refuses, and the refusals are mutually
reinforcing: you cannot spawn because it exists, cannot clean because it has
a ready package, cannot collect or dispose because the package is stale, and
cannot even pause it because its recorded voice contract is from a different
engine install. There is no in-repo verb that opens the cycle.

FINDING 1 -- the third engine divergence, inside the sub-instance
-----------------------------------------------------------------
T-1374 established that three SAIPEN installs exist on this machine and that
`bin/saipen.cmd` runs the `_SAIPEN` one, whose STYLE.md marker is
`ded-71fc58de`. The saihunt sub-agent recorded `ded-6b950e75` -- the marker
of `C:\Users\vac34\.agents\skills\saipen`, the 101-module install. So the
instance was produced by an agent that read a voice contract the launcher
does not use, and the engine now refuses to act on its STATE at all.

This is T-1374's defect, one level down, and it is not repairable from here:
the fix would be to rewrite the recorded `style_contract` to the marker the
instance never read, which is asserting a provenance that did not happen.

FINDING 2 -- two parsers disagree about what a sub board looks like
------------------------------------------------------------------
`sub clean` (tools/sub_clean.py `_open_board_items`) accepts only the four
`## DOING|TODO|DONE|BLOCKED` headings, so it rejects the five `### HUNT-NNN:`
headings in `.saipen/extensions/subs/saihunt/BOARD.md`. The gate's own
sub-board validator accepts that file as it stands.

Converting the five headings to the canonical `- [ ] HUNT-NNN title` form was
tried, measured, and reverted. It does clear the first `sub clean` refusal,
but it makes the gate's validator see the tickets for the first time and then
correctly report a second, deeper incoherence:

  FAIL: .saipen/extensions/subs/saihunt/STATE.md state/board lifecycle is
        incoherent: phase DONE but the board still holds open work
        (TODO/BLOCKED)
  FAIL: .saipen/extensions/subs/saihunt/BOARD.md is phase DONE but its board
        still holds open work (TODO/DOING/BLOCKED)

That is a true statement about this repository -- the saihunt instance
finished while five of its findings are still listed as open BLOCKED work --
and it is not a formatting problem. Trading a `sub clean` refusal for two
gate FAILs is a net loss, so the conversion stays unlanded and is recorded
here instead. The five tickets are real unresolved work; resolving or
re-validating them is the actual subject of the sub-agent's next run, which
is the thing that cannot start.
