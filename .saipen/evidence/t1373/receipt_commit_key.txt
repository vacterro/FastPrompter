  and on this machine SAIPEN_HOME=C:\Users\vac34\AppData\Local\saipen\
  scheduled-source -- a STALE copy. So the project's validator answers from an
  engine generation that predates the fix.

  The four engine-behaviour tests stay green in BOTH states, which is the

  The original draft of this test asserted the opposite of the truth -- it

SECOND DEFECT THIS FOUND (and it made the suite red)
  tests/test_t1358_cohort_publication.py hardcodes the skills home. The first
  draft of THIS file read SAIPEN_HOME, which pointed at the stale copy. Python
  caches saipen_engine in sys.modules on FIRST import, and pytest imports
  alphabetically ("test_r..." before "test_t1..."), so this file silently fixed
  the engine for the entire session. Symptom: the full suite reported 3
  failures, one more than the known baseline of 2 --
  test_closure_stage_includes_cohort_registry failed ONLY in a full run and
  passed in isolation. Pinning this file to the same home restored the
  baseline to exactly 2.

WHAT REMAINS

  installation repair (refresh the scheduled-source copy, or unset SAIPEN_HOME
  so the shim falls back to the skill home) and it lives outside this
  repository -- the same class as T-1374, which already records three divergent
  STYLE.md markers across the same three homes. Not derivable here.
